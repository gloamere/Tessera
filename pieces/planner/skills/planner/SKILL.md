# 方案策划

做非代码的方向性策划(游戏、内容、产品、活动)。产出**能被拍板的方案文档**,不是代码计划。

## 流程

1. **摸清语境**:目标受众是谁?要解决什么?成功长什么样?约束(时间/成本/平台)?先问清,别急着给方案。
2. **调研垫底**(可选):需要外部参照时先走 agent-reach 搜同类做法 / 近期趋势,避免闭门造车。
3. **给 2-3 个方向**,不是一个:每个方向一句话定位 + 核心机制 + 取舍。用 AskUserQuestion 让负责人选。
4. **展开选定方向**:成结构化文档(见下)。
5. **落决策**:方向定了写进 `docs/decisions/`(status: pending → 负责人 approved),交由执行拼图落地。

## 方案文档结构

```markdown
# <方案名>
## 一句话定位
## 目标 & 成功指标
## 核心机制 / 玩法 / 内容
## 关键取舍(为什么不做 X)
## 风险 & 未定项
## 落地拆解(交给 bd-tasks 建 epic)
```

## 硬规则

- **方向属负责人拍板**:不替负责人定死风格 / 玩法基调,用 AskUserQuestion。
- **策划完不等于开工**:落地要建 `docs/decisions/` 文件,approved 后才交执行(见 piece-router 硬规则)。
- 拆解出的执行任务一律进 bd(走 bd-tasks 拼图),不散在文档里。
