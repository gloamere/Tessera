# 方案策划

做非代码的方向性策划(游戏、内容、产品、活动)。产出**能被拍板的方案文档**,不是代码计划。

## 可选本地使用记录

若能定位 Tessera 仓库的 `scripts/usage_events.py`，进入时尝试运行 `start --host <host> --skill planner --project <cwd>`；只有返回事件 id 时，结束前运行 `finish --event-id <id> --host <host> --skill planner --outcome completed|failed --project <cwd>`。默认关闭；记录不可用不得影响策划或增加用户提示。

## 流程

1. **摸清语境**:目标受众是谁?要解决什么?成功长什么样?约束(时间/成本/平台)?先问清,别急着给方案。
2. **调研垫底**(可选):需要外部参照时先走 agent-reach 搜同类做法 / 近期趋势,避免闭门造车。
3. **给 2-3 个方向**,不是一个:每个方向一句话定位 + 核心机制 + 取舍。优先用宿主原生结构化提问让负责人选；不可用时提出简短文本问题。
4. **展开选定方向**:成结构化文档(见下)。
5. **落决策**:目标项目已有决策规范时按规范记录；没有时只在用户明确要求下落盘，不能因为缺少 `docs/decisions/` 阻塞后续工作。

## 方案文档结构

```markdown
# <方案名>
## 一句话定位
## 目标 & 成功指标
## 核心机制 / 玩法 / 内容
## 关键取舍(为什么不做 X)
## 风险 & 未定项
## 落地拆解(按需交给执行方)
```

## 硬规则

- **方向属负责人拍板**:不替负责人定死风格 / 玩法基调，使用当前宿主可用的用户确认方式。
- **策划完不等于自动开工**:先取得负责人确认；只有项目规范或用户明确要求时才写决策文件。
- 拆解出的执行项交给当前 Agent 的原生计划能力。
