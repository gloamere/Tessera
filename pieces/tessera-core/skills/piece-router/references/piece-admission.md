# 拼图准入评判

用户提出新增、引入、拆分或设计拼图时，先完成本评审，再建议是否进入实现或市集。评分只提供一致、可解释的建议；用户仍可选择做临时原型。

## 七维评分（满分 100）

| 维度 | 可选分值 | 证据标准 |
|---|---:|---|
| 需求真实性与复用性 | 20 / 16 / 12 / 6 / 0 | 20：至少 3 次真实任务且跨两个项目或用户；16：同项目重复至少 2 次；12：两个不同代表场景但无真实复用；6：单一具体场景；0：纯假设 |
| 独特价值与增益 | 20 / 16 / 10 / 5 / 0 | 20：无等价能力且收益可验证；16：宿主能做但标准流程显著提高稳定性；10：部分重叠，价值在组合或降摩擦；5：主要是已有 prompt 重包装；0：完全重复 |
| 触发边界与路由清晰度 | 15 / 12 / 8 / 4 / 0 | 15：when/avoid、冲突优先级、正反例齐全；12：主要边界清楚；8：与一块拼图有歧义；4：只能说“可能有帮助”；0：无法可靠路由 |
| 输出契约与可评测性 | 15 / 12 / 8 / 4 / 0 | 15：固定契约、验收、正反例和失败行为齐全；12：缺反例；8：只有示例；4：主要依赖主观判断；0：不可验证 |
| 轻量性与上下文成本 | 15 / 12 / 8 / 4 / 0 | 15：纯 skill、正文约 600 token 内、无外部状态；12：纯 skill 较长或只读写普通文件；8：可选无常驻 CLI，生命周期明确；4：依赖 MCP/daemon/数据库/凭证/持续网络；0：隐式安装、永久状态或成本不可控 |
| 跨宿主与维护成本 | 10 / 8 / 5 / 2 / 0 | 10：Codex/Claude 原生、单一事实来源、版本和卸载明确；8：两端可用但有少量差异；5：一端原生、另一端诚实降级；2：单端且依赖机器配置；0：不可复现或无人维护 |
| 安全性与透明度 | 5 / 3 / 1 / 0 | 5：权限、外部状态、失败、回退明确且可逆；3：少量非关键缺口；1：高权限说明不足；0：隐式安装、破坏性行为或凭证暴露 |

只能使用表中锚点分值；不做无证据的中间分。逐项引用用户提供的事实、仓库现状或验证结果，没有证据就按较低档评分。

## 等级

| 等级 | 原始分数 | 建议 |
|---|---:|---|
| S | 90–100 | 核心级候选，可进入正式实现与发布 |
| A | 80–89 | 推荐新增，补齐少量文档、样例或跨宿主细节后发布 |
| B | 70–79 | 先原型或限定范围试用，凭真实任务复评 |
| C | 60–69 | 不独立成拼图，优先合并或做组合流程 |
| D | 50–59 | 重新定义需求、边界或实现方式 |
| E | 40–49 | 收益低于维护与上下文成本，建议放弃 |
| F | 0–39 | 重复严重、违背原则或有安全风险，拒绝进入市集 |

## 封顶与否决

先计算原始分与原始等级，再应用最严格的等级上限：

- 没有真实使用记录：最高 B。
- 独特价值不超过 5 分：最高 D。
- 触发边界或可评测性不超过 4 分：最高 D。
- 常驻 MCP、daemon、数据库或重型运行时尚无实测收益：最高 C。
- 只支持一个正式宿主且另一端没有诚实降级：最高 C。
- 安全性为 0，或存在静默安装、默认不可逆操作、凭证暴露：直接 F。

## 固定输出

1. **重复问题**：用户想反复解决什么。
2. **现有替代**：宿主能力、已有拼图、组合流程能否覆盖。
3. **七维评分**：逐项分数与证据。
4. **评级**：原始分数与等级、等级上限及原因、最终等级。
5. **标准建议**：新增 / 合并 / 组合 / 原型 / 暂缓 / 拒绝。
6. **升级证据**：进入下一等级还缺什么。

评级段必须使用下面格式：

```text
原始分数：84/100（A）
等级上限：B（尚无真实使用记录）
最终等级：B
建议：先原型验证，不进入正式市集
```
