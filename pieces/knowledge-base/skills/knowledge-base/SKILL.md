# 个人知识库

轻量方式沉淀知识:一则一文件,markdown + 双链,可被 grep 检索。**不上向量库**——个人规模用文件 + 搜索足够。

## 一则笔记的结构

```markdown
---
title: <一句话主题>
tags: [领域, 类型]
created: <YYYY-MM-DD>
---

<核心结论,一段话说清>

## 展开
...

## 关联
- [[其它笔记标题]]
```

## 原则

1. **一则一事**:一个文件只讲一个可复用的点,标题就是它的结论。
2. **原子化优先于完整**:宁可多个小笔记 + 双链,不要一个大杂烩。
3. **双链代替目录**:用 `[[标题]]` 关联,让结构自然浮现,不预建深层文件夹。
4. **先写结论**:每则开头一段直接给结论,展开在后。
5. **可检索 > 可浏览**:tag + 正文关键词能被 grep 到即可。

## 操作

| 意图 | 做法 |
|---|---|
| 记一条 | 知识库目录新建 `<kebab-标题>.md`,套上面结构 |
| 找资料 | grep tag / 关键词;顺双链 `[[...]]` 展开 |
| 整理主题 | 建一则「索引笔记」,正文列 `[[...]]` 链到各原子笔记 |
| 定期回顾 | 按 created / tag 过滤,合并重复、补断链 |

## 与其它拼图

- 需搜集新资料 → 先使用宿主当前可用的搜索、浏览器或连接器，再把结论沉淀成笔记。
- 要真·RAG(百万级文档语义检索)才考虑接 llama_index / milvus 后端(见 registry 候选后端),个人规模不必。
