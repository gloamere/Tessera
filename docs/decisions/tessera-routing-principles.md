# 第一阶段路由原则

## 定位与可演进性

本决策只定义 Tessera 第一阶段的默认行为,不是永久架构边界。新拼图、真实路由评测、宿主能力变化或用户工作流证据足以推翻其中任何一项时,应新增或更新决策并标注本文件为 `superseded`,而不是被初版设计束缚。

Tessera 的目标是"拼图管理 + 任务路由:自动调用合适拼图协助完成任务",同时优化完成质量、token 消耗与等待时间。

## 执行分层

| 任务形态 | 默认动作 | 不做什么 |
|---|---|---|
| 单一、明确、低风险 | 当前 agent 直接完成 | 不为小改动强制进入路由或专业拼图 |
| 单一、明确,但存在已安装且明显更专业的拼图 | 直接调用该拼图 | 不先经过复杂路由;只有收益大于额外 token/时间时才调用 |
| 模糊、跨领域、需要选择工作流 | `piece-router` 识别意图并选择下一步 | 不把未安装、未验证或规划中的能力伪装为可用 |
| 可拆成独立子任务的复杂工作 | 宿主支持时条件委派子代理,主 agent 汇总 | 不因"复杂"就盲目并行;不并发修改同一写入面 |

## 任务追踪

- 任务追踪一律走 `bd-tasks`(bd/Beads);**禁止 TodoWrite、禁止 markdown TODO 列表**(见全局约定)。
- 会话内短期步骤、执行顺序可用宿主 agent 的计划能力辅助思考,但产生的工作项落 bd,不留在对话里。
- 未安装 Beads 时,先 `bd ready` 探测;报 "no beads database" 时问用户是否 `bd init`。

## 路由质量

路由是否调用拼图以净收益为标准:预期质量提升必须大于额外 token、调用延迟与上下文切换成本。路由规则应随着已安装拼图及评测样例演进。

子代理同样遵循净收益原则:仅在宿主提供委派能力、子任务独立、写入面隔离且并行收益大于协调成本时启用。主 agent 始终保留集成、冲突处理、验证和最终交付责任;条件不满足时退回直接执行或专业 skill。
