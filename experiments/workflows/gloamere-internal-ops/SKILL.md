# 内部运营（实验）

把非软件的内部运营问题转成有负责人、有控制点、有例外处理的执行方案。本候选 Skill 保留在 `experiments/workflows`，不属于已发布插件。

## 范围

- 适用：供应商选择或续约、跨团队流程、SOP、RACI、业务变更、容量与排班、运营风险和管理状态报告。
- 不适用：代码或基础设施变更、生产事故响应、财务记账、增长活动、产品功能方向。
- 法律、劳动关系、隐私与安全结论交给相应负责人；本 Skill 只整理事实、选项与待审事项。

## 工作流程

1. 定义目标、服务对象、起止边界、当前负责人、最终审批人和不可违反的政策。
2. 收集现状证据：流程记录、合同或政策、工作量、时限、历史异常和已知控制；未知项单列。
3. 标出瓶颈、重复交接、单点依赖、容量缺口、控制缺口和异常升级失败点。
4. 比较维持现状与候选方案的成本、风险、可逆性、人员影响和迁移难度。
5. 为推荐方案列出行动、负责人、审批人、截止时间、依赖、完成证据和升级条件。
6. 定义试运行范围、运营指标、复查时间、停止条件和回退步骤。

## 产物契约

- **供应商评估**：需求、候选、总成本、服务连续性、数据与合同风险、依据、谈判项和待批准建议。
- **SOP**：触发条件、前置条件、步骤、输入与输出、控制点、异常分支、升级路径、版本和复查日期。
- **RACI**：每项活动只有一个最终负责者，区分执行、最终负责、咨询和知会角色。
- **变更方案**：目的、影响、依赖、验证、沟通、培训、审批、窗口、回退和成功标准。
- **容量计划**：需求假设、现有容量、利用率、情景、缺口、资源选项和触发阈值。

## 控制边界

未经明确授权保持只读，不签合同、不批准变更、不发送外部通知、不修改生产系统或合规记录。流程复杂度应匹配风险；低风险一次性任务不强行扩写为完整 SOP。
