# UI 能力模块

UI 工作包由总指挥组合 brief、`docs/ui/TASTE.md`、设计系统、参考资产与一个适配器完成。适配器提供方法，不取代项目事实源或负责人的最终审美判断。

## 选择顺序

1. 读取 UI brief、现有客户端/前端约束和 `docs/ui/TASTE.md`。
2. 若“页面对象、目标玩家、优先问题或验收方式”存在会改变方案的歧义，先走澄清门；不要用泛泛的“再高级一点”开始生成。
3. 选择最小适配器。`taste-skill` 适合做设计解读、反套路审查和视觉复盘；它不是游戏客户端的组件库或实现规范。
4. 先产出明显不同的方向与实现风险，等待负责人拍板；再派实现 agent。
5. 以目标分辨率截图复查层级、可读性、一致性与操作路径，并把有效偏好写回 TASTE。

## 游戏客户端限制

- `taste-skill` 的网页营销页、GSAP、长滚动叙事和宽松留白规则不默认适用于高信息密度的游戏客户端。
- 客户端优先级是：关键入口可见、战斗/操作不遮挡、分辨率适配、资源与性能预算、现有控件实现成本。
- 不因 skill 建议而改变已拍板的世界观、数值信息层级或平台限制。
