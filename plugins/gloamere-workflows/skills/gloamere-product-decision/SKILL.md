# 产品决策

把分散证据收敛为可拍板、可复查、可证伪的产品选择。完整模板不是目标；决策理由、未知项和验证路径才是核心。

## 边界

- 使用已经提供或通过获授权来源取得的研究与数据；不模拟受访者，也不声称已经完成访谈或可用性测试。
- 产品功能、体验和范围取舍属于本 Skill；获客渠道、内容活动和转化运营属于独立的增长执行流程。
- 已确定方向后的工程拆解、排期和代码修改交给项目实施流程。

## 决策流程

1. **定义决策**：写清目标用户、场景、待解决问题、业务目标、约束、决策期限和最终拍板人。
2. **建立证据账本**：分开记录事实、来源与日期、观察、假设、冲突证据和未知项；标明证据强弱。
3. **形成可比较选项**：至少包含维持现状或延后、低成本验证方案和主要候选方案，避免只论证最初想法。
4. **说明取舍**：比较用户价值、业务价值、成本、风险、可逆性、依赖和学习速度。缺少数据时用定性判断并说明原因，不伪造精确分数。
5. **收敛范围**：列出范围内、范围外、关键场景、必要状态、依赖和验收边界。
6. **定义结果**：为成功指标写明基线、目标、时间窗口、数据源、护栏指标和停止条件。
7. **安排验证**：找出最危险且尚未证实的假设，设计成本最低的下一步实验，并明确负责人、证据门槛和复查时间。

## 按任务输出

- **机会简报**：用户问题、证据、规模或频率、现有替代方案、机会边界、建议与待验证项。
- **研究综合**：样本与局限、主题、反例、证据强度、产品含义；不把原始笔记数量当结论。
- **PRD 决策**：问题、目标与非目标、选择及理由、范围、关键场景、验收边界、指标、风险和开放问题。
- **路线图取舍**：结果目标、候选事项、依赖、置信度、Now/Next/Later 和触发调整的信号。

## 输出契约

先给推荐选择和待拍板事项，再给证据、备选方案与取舍。结尾必须包含成功指标、主要风险、开放问题和下一验证动作。信息不足时提供带假设的暂定结论，并明确哪些新证据会改变建议。
