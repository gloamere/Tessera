# 知识沉淀

把已有材料转成可追溯、可检索、可继续维护的知识记录。优先融入现有知识库，不擅自建立另一套目录、字段或链接语法。

## 写入前

1. 确认目标目录、受众和用途。个人笔记侧重回忆线索；团队知识还要明确状态、负责人和适用范围。
2. 阅读目标目录中的说明、索引、模板与相邻笔记，识别文件名、frontmatter、标题层级和链接约定。
3. 搜索相同标题、别名、关键词和相关链接，判断应更新现有记录、合并重复内容，还是新建记录。
4. 若目标目录缺失且不同选择会改变归属或权限，先请求用户决定；不要把文件写到猜测的位置。

## 沉淀方式

- 先写可复用结论，再补背景、依据、适用条件和例外。
- 区分已确认事实、推断、决定、待办与开放问题；每条关键结论保留来源或形成日期。
- 沿用现有字段。没有约定时使用最小元数据：`title`、`status`、`updated`、`sources`、`aliases`；团队记录再增加 `owner`。
- 链接使用知识库现有语法。支持 wiki 链接时使用 `[[标题]]`；否则使用相对 Markdown 链接，不混用两套格式。
- 一次讨论涉及多个可独立维护的主题时可以拆分，但必须保留入口索引和双向可发现关系。

## 常见模式

- **对话或会议沉淀**：记录背景、决定、理由、负责人、截止时间和未决项；不把完整聊天逐字搬入。
- **研究综合**：按主题汇总相符证据、反例、来源日期和置信度；不把单一来源写成共识。
- **经验维护**：更新过时步骤与状态，保留必要的变更说明，并修复受影响的索引和链接。

## 完成检查

- 文件名与标题不冲突，重复内容已合并或明确区分。
- 所有新增内部链接都能解析，重命名没有留下断链。
- 来源、状态、负责人和日期与目标知识库契约一致。
- 不写入密码、Token、完整连接串或与长期知识无关的敏感原文。

交付时简要列出新增、更新、合并的记录以及仍需确认的链接或事实。没有写入权限或用户只要草稿时，给出目标路径和可直接保存的内容，不声称已经落库。
